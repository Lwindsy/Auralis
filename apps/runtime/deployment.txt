Auralis Linux 容器部署

入口：compose.yml；在仓库根构建 java.Dockerfile、python.Dockerfile、web.Dockerfile。
前端先运行 npm --prefix apps/frontend ci 和 npm --prefix apps/frontend run build。
Java、Python、Caddy使用Linux宿主网络，保留内部literal-loopback约束。
PostgreSQL只映射127.0.0.1:15439，数据位于auralis_database命名卷。
Caddy仅公开前端和/v1/，内部及管理端点返回404。

运行准备（首次部署由运维执行，不由CI创建或复制音乐数据）：
- /etc/auralis/{database,java,python,migrate,web}.env：root所有、权限600；
  分别注入数据库管理员、普通在线账号、Python模型密钥、离线迁移身份和域名。
  Java无模型密钥，Python无数据库凭据；这些文件不得提交或打进镜像。
- /etc/auralis/config/{agent-service,models,recommendation}.json：显式部署配置。
- /opt/auralis/data/{index,taxonomy,curated}与audience.json：已核验工件，只读挂载。
- 新空库先创建auralis_migrator和auralis_online，再运行migrate服务。
  目录与全量Audience须从已核验来源迁入并逐表对账；不能把空表当作已部署。
- Caddy 直接公开时，web.env 的 AURALIS_HOSTNAME 与 java.env 的
  AURALIS_PRODUCT_ORIGIN 须对应同一 HTTPS 源。修改域名后重建 Java、Caddy，沿用数据卷。

Cloudflare 前端与同源 API
- 正式入口为 https://auralisy.online。切换前在 Cloudflare 配置访客 HTTP 到 HTTPS
  的跳转，并确认边缘证书有效。Java 的 AURALIS_PRODUCT_ORIGIN 设为完整 HTTPS 源。
- 在 VPS 配置 Cloudflare Tunnel，公开主机名使用 auralisy.online，服务地址为
  http://127.0.0.1:18081。通过 root 专用配置管理 Tunnel 凭据。在 web.env 设置
  AURALIS_WEB_MODE=tunnel-web，通过发布流程排空并重建 Java、Caddy。Caddy 只监听
  127.0.0.1:18081，沿用 /v1/ 转发和容器内的同版静态文件。核对旧公网 HTTP(S)
  监听已退役，并按实际网络配置收口 Web 入站，保留独立 SSH 管理入口。
  VPS 连接器为 auralisy-cloudflared，使用 cloudflared 2026.11.0 的固定镜像摘要，
  凭据从 /etc/auralis/cloudflare/tunnel-token 只读挂载。用回环地址
  http://127.0.0.1:18082/ready 检查连接状态，使用 docker logs auralisy-cloudflared 排障。
- 先验证 Tunnel 提供首页和 /v1/bootstrap，再配置 Workers Routes。添加较具体的
  auralisy.online/v1/* 路由，Worker 选 None，让 API 经 Tunnel 到 Caddy。添加
  auralisy.online/* 路由绑定 auralisy-frontend，提供 Workers Static Assets。
  这两条使用 Workers Routes，DNS 继续指向 Tunnel。/v1/* 设为绕过 Cloudflare
  缓存。客户端继续使用同源路径，Cloudflare 不执行 API 的 Worker 代码。
- 免费限速按 IP 对推荐提交、换批、复筛、卡片操作和长评打开／重生成路径合并计数。
  超过 20 次／10 秒时阻断 10 秒。目录搜索与状态轮询不在该规则内。
- GitHub 变量 CLOUDFLARE_ACCOUNT_ID 与 Secret CLOUDFLARE_API_TOKEN 启用同版静态发布。
  首次创建 Worker 使用目标账户的管理会话，持续发布凭据授予该 Worker 的 Editor 权限。
  路由在 Cloudflare 控制台管理，首次可先发布静态文件，再绑定正式域名的路由。
  工作流先检查静态发布配置，再发布 VPS 和静态文件，最后核验 PRODUCT_URL。
  PRODUCT_URL 使用新入口，无末尾斜杠。正式域名模式要求先配置 Cloudflare 发布凭据，
  避免只更新 VPS 并继续用旧版静态前端。切换前版本的镜像仍需挂载 Tunnel Caddyfile，
  才能在该版本回退时保留回环监听。
- 首次切换核对 HTTPS、首页与静态资源版本、bootstrap 的 Secure/HttpOnly/SameSite
  Cookie、目录搜索、策展推荐和关闭重开后的恢复。验证拒绝跨站写入、个人响应
  不进共享缓存，核对内部和管理路径不可访问。旧域名的匿名 Cookie 无法带到新域名。
  旧站退役前用 HTTPS 410 和 Max-Age=0 清除访问到该响应的匿名 Cookie。公网 Web
  端口关闭后，其余浏览器上的旧 Cookie 按原有效期过期，原会话数据按原保留规则清理。
- 若静态发布失败或新旧前后端跨版，移除 auralisy.online/* 的 Worker 路由，原域名
  即可经 Tunnel 使用 Caddy 容器内的同版页面。确认首页、bootstrap 和同一 Cookie
  的恢复后再恢复边缘路由。旧版本回退仍按下文的镜像、工件和数据库兼容条件执行。

CI/CD：.github/workflows/ci.yml
只改根目录的README.md、README_ZH.md时，main推送和目标为main的PR跳过工作流。
含其他文件的PR运行检查；main推送或在main手动执行通过检查后自动部署。
检查包含Python Ruff、Pytest、Java Spotless及构建、前端类型/格式检查、单元测试及构建。
独立PostgreSQL另运行执行状态轮询的锁竞争回归，防止短暂行锁导致推荐中断。
GitHub Secrets：DEPLOY_HOST、DEPLOY_KEY、DEPLOY_KNOWN_HOSTS。
GitHub变量：PRODUCT_URL（无末尾斜杠）。SSH主机密钥须独立核验，不临时自动信任。
发布包只包含git archive产品内容与已检查前端dist，不包含私有工作资料。

部署由 apps/runtime/deploy.sh <40位提交SHA> 执行：
1. 在/opt/auralis/releases/<SHA>构建三个带SHA标签的镜像。
2. 排他锁防止重叠部署。先停止网页接纳请求，再进入维护，最多等待210秒排空执行槽与等待队列。
3. 停止网页和双端；pg_dump备份至/opt/auralis/backups。
4. 使用独立迁移身份执行Flyway并更新在线账号授权。
5. 启动Python/Java，确认readiness后启动网页；CI再验证公网HTTPS及bootstrap。
数据库卷、工件、配置和身份签名密钥不会随镜像更新被替换。
Compose 的 Java 执行窗口默认 180 秒，自请求接收时起算，包含并行生成的长评。
发布时可用 AURALIS_DISPATCH_EXECUTION_SECONDS 收紧。回退到只支持 120 秒的镜像时，
使用旧版 Compose 并将该值设为至多 120 秒，账本由现有数据库承接。
首次运行与后续版本均须实测，不把镜像构建成功视为推荐链路验收。

失败与回退：
构建失败不切换现有服务。排空超时保留维护状态，先核查在途请求；不杀任务掩盖失败。
迁移或readiness失败时网页保持停止，保留备份和诊断，不自动恢复旧数据库。
没有双版本并行兼容期；每次部署使用同一SHA的Java/Python/前端。
若数据库迁移未变化且旧版兼容当前配置、工件，可对旧release执行deploy.sh回退。
若DDL已经变化，先核对Flyway及兼容性；优先前滚，不自动启动不兼容旧应用。
数据库恢复必须到新隔离库，核对备份后的账单与删除屏障，再按恢复手册切换；
无法补齐删除记录时轮换身份签名密钥。不得删除卷或回写迁移历史伪装回退。
已发出的模型调用费用及用户操作不可通过容器回退撤销。

当前不设置全站每日费用上限；会话、轮次、车道预算仍由Java配置控制。
备份在本机保留，需要运维定期复制到独立存储；容器更新不替代异机备份。

模型与预算配置同步
- 发布使用服务器 /etc/auralis/config 下的外置文件。CI/CD 更新镜像并继续挂载该目录。
- 从真实开发预览的运行记录确认实际加载的配置。逐项核对 models.json 的模型绑定与
  recommendation.json 的 model_bindings、prices、budget_limits，包含输入／输出 token、
  费率、调用次数和会话／轮次／车道金额。核对 agent-service.json 的服务参数，沿用生产
  工件路径、控制地址和凭证环境。开发预览启动器的整场试验费用上限只适用于该次预览。
- 按新配置核对单次调用最大预留能落在对应车道预算内。
- 先按发布流程停止网页接纳并排空旧执行，在双端停止后备份并同步两份配置，
  再启动同版 Java／Python。核对容器实际挂载的配置与开发基准、Java readiness 和维护
  状态后恢复网页，再验证公网 HTTPS 与 bootstrap。
- 同一模型身份、版本及费率下，旧会话后续执行采用更新后的 token 上限，已有轮次保留
  原金额和调用次数，历史执行、预留和结算记录继续留存。配置回退按同一排空流程恢复
  成对备份并复核 readiness。恢复服务使用现有数据库和账本。
